# Автосервис API

Для обычного запуска откройте терминал в корне проекта и выполните:

docker compose up -d
docker compose logs -f db-seed

Дождитесь сообщения об успешном выполнении сида, затем нажмите Ctrl+C — это остановит только просмотр логов. Контейнеры продолжат работать.

Дальше:

Во втором терминале запустите API: npm run start:dev
В третьем (если нужна Prisma Studio): npx prisma studio

## Swagger

После запуска API документация доступна по адресу `http://localhost:3000/api/docs`.
Одна OpenAPI-документация охватывает все HTTP-маршруты; теги группируют их по
назначению, а не по используемой базе данных.

## Сервисы разработки

- PostgreSQL — порт `5433` на компьютере (`5432` внутри Docker)
- MongoDB — порт `27017`
- NestJS API — порт `3000`

Обе базы запускаются через `docker compose up`. После готовности PostgreSQL
сервис `db-seed` применяет Prisma-миграции и загружает учебные данные из
`prisma/seed.sql`.

Сид сбрасывает таблицы приложения перед заполнением, поэтому повторный
`docker compose up` возвращает PostgreSQL к исходному учебному набору данных.
Данные PostgreSQL и MongoDB находятся во временной памяти (`tmpfs`) и теряются
при остановке или перезапуске контейнеров. Не запускайте этот Compose-набор для
хранения нужных данных.

## Хранение данных

### PostgreSQL через Prisma

Prisma ORM 7 используется для работы с реляционными данными: клиентами, автомобилями, заказами, работами, запчастями и складскими движениями. Схема находится в `prisma/schema.prisma`, а NestJS получает доступ к сгенерированному Prisma Client через `PrismaService` и PostgreSQL-адаптер `@prisma/adapter-pg`.

Изменения структуры PostgreSQL оформляются Prisma-миграциями. После изменения схемы нужно сгенерировать клиент командой `npx prisma generate`; для создания и применения миграции в разработке используется `npx prisma migrate dev`.

### MongoDB через Mongoose

MongoDB предназначена для документов с гибкой структурой: событий заказа, комментариев мастера и дефектных листов с фотографиями. Эти данные не добавляются в `prisma/schema.prisma`: Prisma Client в текущем проекте обслуживает PostgreSQL, а установленная Prisma 7 не поддерживает MongoDB.

NestJS подключается к MongoDB через Mongoose при старте приложения. Для подключения задайте переменную `MONGODB_URL` в корневом `.env`; локальный адрес и настройки авторизации должны соответствовать сервису `mongodb` в `docker-compose.yml`. Если переменная не задана, приложение завершит запуск с явной ошибкой.

В MongoDB реализован журнал `order_events`:

- `POST /orders/:id/events` добавляет событие типа `comment` или `defect` с объектом `payload`;
- `GET /orders/:id/events` возвращает историю заказа от новых событий к старым;
- создание заказа и изменение его статуса записываются автоматически;
- `GET /orders/events/monthly?month=YYYY-MM` группирует события выбранного месяца по типу.

Индекс `{ orderId: 1, at: -1 }` ускоряет историю заказа; TTL-индекс удаляет события старше двух лет (MongoDB выполняет удаление в фоне, не точно в момент истечения срока). Дефектный лист хранится как произвольный объект в `payload`; фотографии передаются как пути/ссылки, сами файлы этим API не загружаются.

Запись события выполняется после коммита операции PostgreSQL и не входит в общую транзакцию с ним. Поэтому при недоступности MongoDB API сообщит об ошибке, хотя изменение заказа в PostgreSQL уже могло сохраниться. Для гарантированной доставки событий потребуется outbox в PostgreSQL и повторная публикация в MongoDB.
